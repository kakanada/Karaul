# Karaul

Karaul is an SSH login watch for one server. It tells the owner in Telegram when a sign-in comes from an address that is not on the whitelist.

Караул следит за входами по SSH на одном сервере и пишет владельцу в Telegram, если адрес входа не из белого списка. Входы из белого списка попадают в журнал и не вызывают тревогу.

Бот отвечает только человеку, чей числовой id записан в `owner_id`. Сообщения и нажатия кнопок от остальных аккаунтов бот отбрасывает и ничем не отвечает.

Один бот обслуживает один сервер. Для второго сервера нужен второй бот и свой конфиг. Кнопки и тексты тревог на русском. Время в журнале и в тревоге — московское. Кнопка **Статус** показывает часы самого сервера, в его часовом поясе.

Караул сообщает о входе. Пускать ли этот адрес по SSH, решает `sshd`: белый список не открывает и не закрывает порт.

## Что умеет

- Клавиатура под полем ввода: **Белый список**, **Последние входы**, **Добавить IP**, **Удалить IP**, **Статус**, **Помощь**.
- Карточка входа: время до секунды, пользователь, IP, место, провайдер, отметка белого списка.
- Тревога на адрес вне списка. Сообщение уходит сразу, ещё до запроса места. Место и провайдер дописываются в то же сообщение, когда справочник ответит. В начале стоит красный знак и строка **КТО-ТО НЕ ТОТ ЗАШЁЛ**.
- Статус сервера: короткая оценка, имя хоста, внешний IPv4, место, часовой пояс, провайдер, время работы, загрузка CPU, load average, память, swap, диски, имена сайтов nginx и сертификаты без сайта.
- Журнал `/var/log/karaul/access.log` и копия в syslog с именем `karaul`. Файл не растёт дальше 128 МБ: при переполнении остаётся хвост около 32 МБ.
- Комментарий к каждому адресу белого списка, до 80 символов.

Оценка в статусе — `норма`. Отдельной строкой бот напишет, если CPU от 85%, свободной памяти меньше 10% или на диске свободно меньше 10%.

## Что нужно на сервере

- Linux с systemd и OpenSSH. Шаги ниже рассчитаны на Debian и Ubuntu: хук ставится в `/etc/pam.d/common-session`.
- Python 3.9 или новее. Хватает стандартной библиотеки, отдельно ничего ставить не нужно.
- Команды `python3`, `ip` и `df`. Список доменов заполняется, если установлен `nginx`.
- Root. Служба работает от root: так PAM может вызвать скрипт, а журнал лежит в системном каталоге.
- Исходящий HTTPS на `api.telegram.org` и исходящий HTTP на `ip-api.com` для места и провайдера.

## 1. Создать бота

1. В Telegram открой [@BotFather](https://t.me/BotFather).
2. Отправь `/newbot` и пройди вопросы. Имя и username выбираешь сам.
3. BotFather пришлёт токен вида `123456789:AA...`. Это пароль бота. Он хранится только в конфиге на сервере и в git не попадает.
4. Узнай свой числовой id. Напиши `/start` боту [@userinfobot](https://t.me/userinfobot): в ответе будет число, например `111111111`.
5. Открой личный чат со своим новым ботом и нажми **Start**. Пока этого нет, Telegram не доставляет тебе сообщения бота.

## 2. Положить файлы

Скопируй этот каталог на сервер и выполни:

```bash
sudo bash install.sh
```

Скрипт раскладывает файлы так:

| Файл в каталоге | Куда ставится | Права |
| --- | --- | --- |
| `karaul.py` | `/opt/karaul/karaul.py` | `755` |
| `on_login.sh` | `/opt/karaul/on_login.sh` | `755` |
| `karaul.service` | `/etc/systemd/system/karaul.service` | `644` |
| `config.example.json` | `/etc/karaul/config.json`, только если файла ещё нет | `600` |
| `whitelist.example.txt` | `/etc/karaul/whitelist.txt`, только если файла ещё нет | `644` |

Он создаёт `/var/log/karaul` и `/var/lib/karaul` и добавляет одну строку в PAM. Службу он не запускает. Уже существующие конфиг и белый список не перезаписывает.

## 3. Заполнить конфиг

Открой `/etc/karaul/config.json`:

```json
{
  "token": "123456789:replace-with-the-token-from-botfather",
  "owner_id": 0,
  "server": "203.0.113.10",
  "place": "",
  "provider": ""
}
```

| Поле | Что писать |
| --- | --- |
| `token` | Токен из BotFather. |
| `owner_id` | Твой числовой id Telegram. Тревоги приходят в этот чат. Команды с любого другого id игнорируются. |
| `server` | Имя, которое видно в тревоге и в кнопках. Адрес или короткое имя сервера. |
| `place` | Необязательно. Текст места в статусе, например `Berlin, Germany`. Пустая строка — место возьмётся из справочника по IP. |
| `provider` | Необязательно. Текст провайдера в статусе. Пустая строка — из справочника. |

`203.0.113.10` — адрес из диапазона для документации. Поставь свой.

Оставь файл читаемым только для root:

```bash
sudo chmod 600 /etc/karaul/config.json
```

## 4. Белый список

`/etc/karaul/whitelist.txt`: один адрес на строку. Текст после первого пробела — комментарий.

```text
203.0.113.10 office
203.0.113.11 home
```

Строки с `#` пропускаются. До запуска службы впиши адреса, с которых заходишь сам. Вход с адреса вне списка пришлёт тревогу.

После запуска список меняется из бота:

- **Добавить IP**, затем сообщение `1.2.3.4 офис`. То же делает `/add 1.2.3.4 офис`.
- **Белый список** показывает адреса. Кнопка с карандашом у адреса просит комментарий. Один символ `-` снимает комментарий. То же делает `/comment 1.2.3.4 офис`.
- **Удалить IP** показывает текущий список. Нажатие на адрес спрашивает подтверждение. То же делает `/del 1.2.3.4`.

## 5. Хук на вход

`install.sh` дописывает в `/etc/pam.d/common-session`, если такой строки ещё нет:

```text
session optional pam_exec.so type=open_session /opt/karaul/on_login.sh
```

`optional` значит: ошибка внутри Караула не обрывает SSH-сессию. `on_login.sh` сразу выходит, если это не вход по SSH, и только тогда запускает `karaul.py record`.

Строка стоит в общем файле сессий, а скрипт сам отсекает всё, кроме `sshd`. Входы через sudo и локальная консоль в журнал не пишутся.

## 6. Запустить

```bash
sudo systemctl enable --now karaul.service
sudo systemctl status karaul.service
```

Служба держит одно долгое соединение с Telegram. На один токен — один такой процесс. Второй процесс с тем же токеном получит ошибку HTTP 409, и оба перестанут получать обновления.

В чате бота отправь `/help`. Внизу появится клавиатура. Если бот молчит, проверь `owner_id` и что в личном чате с ботом нажат **Start**.

Журнал службы:

```bash
sudo journalctl -u karaul.service -n 50 --no-pager
```

## 7. Проверить на живом входе

Зайди по SSH с адреса, который уже есть в белом списке. Нажми **Последние входы**. Новая строка должна быть в списке с пометкой белого списка, тревога при этом не приходит.

Чтобы увидеть тревогу, зайди с адреса, которого в списке нет. Сообщение начинается с красного знака и строки **КТО-ТО НЕ ТОТ ЗАШЁЛ**, дальше сервер, пользователь, IP и время. Место и провайдер дописываются следом.

## Журнал

Строка входа:

```text
2026-01-02 03:04:05 МСК | вход | пользователь=admin | ip=203.0.113.10 | место=... | провайдер=... | белый_список=да
```

Изменения списка пишутся как `| команда |`. Те же строки уходят в syslog, подсистема `auth`, имя программы `karaul`.

**Последние входы** показывают 64 последних входа, по пять на страницу, сначала новые. Кнопки **← Раньше** и **Новее →** листают страницы.

## Файлы на сервере

| Путь | Зачем |
| --- | --- |
| `/opt/karaul/karaul.py` | Программа. |
| `/opt/karaul/on_login.sh` | Точка входа из PAM. |
| `/etc/karaul/config.json` | Токен, владелец, имя сервера. Права `600`. |
| `/etc/karaul/whitelist.txt` | Адреса и комментарии. |
| `/var/log/karaul/access.log` | Журнал. |
| `/var/lib/karaul/offset` | Курсор обновлений Telegram. |
| `/var/lib/karaul/pending` | Ожидание адреса или комментария, если бот его попросил. |
| `/etc/systemd/system/karaul.service` | Служба. |

## Обновление

Замени `/opt/karaul/karaul.py` и `/opt/karaul/on_login.sh`, затем:

```bash
sudo systemctl restart karaul.service
```

`config.json`, белый список и журнал оставь на месте.

## Удаление

```bash
sudo systemctl disable --now karaul.service
sudo rm -f /etc/systemd/system/karaul.service
sudo systemctl daemon-reload
sudo rm -f /opt/karaul/karaul.py /opt/karaul/on_login.sh
```

Убери строку `karaul` из `/etc/pam.d/common-session`. Каталоги `/etc/karaul`, `/var/log/karaul` и `/var/lib/karaul` удаляй, когда токен, список и журнал больше не нужны.

## Что коммитить

В этом каталоге примеры конфига и белого списка без настоящего токена, id и адреса сервера. Не добавляй в git заполненный `/etc/karaul/config.json` и рабочий белый список. `.gitignore` отсекает файлы с именами `config.json` и `whitelist.txt`, если их скопируют в рабочее дерево.
